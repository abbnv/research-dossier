# Карта исследовательских задач

`question-map.md` is the pre-search contract. It should be broad enough to discover unexpected material and specific enough that every branch has a clear harvest target. It is not a choice between finished video angles.

## Required opening

Start with:

- the topic and source material;
- what the viewer should understand, feel, question, or try after the video;
- the main question or tension;
- known assumptions and constraints;
- optional editorial focus, if the user already has one.

Ask only questions that can change the research. Generate five mutually useful options for each question and explain briefly why the choice matters. If the input is already clear, skip the question and build the map.

## Research branches

Create only the branches relevant to the topic, usually from this set:

1. **Mechanism:** how the phenomenon works and what causes or maintains it.
2. **Evidence:** studies, data, methods, results, population, limits, and generalizability.
3. **Neighboring explanations:** similar concepts, competing models, differences, and overlap.
4. **Human dimension:** documented cases, people, conflict, stakes, turning points, and what can be shown.
5. **Practical layer:** what the findings change for the viewer, possible actions, and safe experiments.
6. **Criticism:** counterarguments, failed predictions, alternative explanations, and overreach risks.
7. **Intellectual context:** quotations, books, lectures, films, videos, interviews, and essays.
8. **Creative translation:** metaphors, visual mechanisms, comparisons, thought experiments, and unusual concepts.

## Harvest target for every branch

Each branch must say what a useful answer should produce:

- a plain-language answer;
- important sources or an explicit evidence gap;
- a human or visual example where possible;
- useful quotations or related references where relevant;
- a two- or three-sentence scenario application;
- unresolved questions and follow-up searches.

## Confirmation

End with the exact map status, the user's edits, and the confirmation date. Do not begin the broad research pass until the user confirms, unless they explicitly ask the assistant to proceed autonomously.
